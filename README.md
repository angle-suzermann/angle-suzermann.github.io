# Материалы ANGLE

Интерактивные задания по английскому языку. Автор — Viktoria Syuzyova.

Статический сайт на GitHub Pages. Материалы пишутся как обычные HTML-страницы,
каталоги генерируются автоматически из метаданных внутри самих страниц.

**Настраиваете в первый раз? → [START-HERE.md](START-HERE.md)**
**Вы Claude или другой агент? → [CLAUDE.md](CLAUDE.md)**

## Как это работает

```
материал = <курс>/<slug>/index.html  с блоком <meta name="ws:*">
                    ↓  push в main
        GitHub Actions запускает node build.mjs
                    ↓
   _site/ с лендингом, страницами курсов и панелью преподавателя
                    ↓
              GitHub Pages
```

Добавить материал — положить папку. Каталог обновится сам, руками ничего вести не надо.

## Адреса

| Что | Адрес |
|---|---|
| Заглавная | `/` — намеренно без списка материалов |
| Страница курса, для учеников | `/as4/`, `/as5/` — только опубликованное |
| Панель преподавателя | из `site.config.json`, поле `staffPath` |
| Каталог для агентов | `/catalog.json` |

Сайт закрыт от поисковиков: `noindex` на каждой странице плюс `robots.txt`.
Это внутренний ресурс школы, но не секретный — кто знает ссылку, тот откроет.
`robots.txt` действует, только если сайт в корне домена; основная защита — `noindex`.

**Публикация в подпапке.** Материалы пишутся с абсолютными путями (`/assets/…`).
Если репозиторий назван не `ЛОГИН.github.io`, сайт живёт по адресу
`ЛОГИН.github.io/имя-репозитория/` — тогда в `site.config.json` надо заполнить
`basePath: "/имя-репозитория"`, и сборка подставит префикс во все `href`, `src`
и `url()`. Для репозитория `ЛОГИН.github.io` поле остаётся пустым.

## Локально

```bash
node build.mjs                        # собрать в _site/, проверить материалы
python3 -m http.server 8080 -d _site  # посмотреть
```

Нужен только Node 18+. Зависимостей нет: ни `package.json`, ни `node_modules`.

`build.mjs` падает с ненулевым кодом, если у материала не заполнены метаданные,
`course-id` не совпадает с папкой, есть кнопка отправки без адреса Formspree
или внутри страницы осталась картинка в base64. Так кривой материал не уедет в прод.

## Структура

```
site.config.json   курсы, ярлыки Formspree, адрес панели преподавателя
build.mjs          сборка и проверка, ~330 строк, без зависимостей
assets/            общее для всех материалов
  angle.css          бренд: Apercu Pro, палитра, шапка с логотипом
  test.css           структура тестов (цвета задаёт сам материал)
  test-engine.js     подсчёт баллов и отправка результата учителю
  catalog.css        оформление каталогов
_templates/        заготовки: test.html, worksheet.html
.claude/skills/    скиллы: new-test, new-worksheet, check-material,
                   import-material, publish
as4/ as5/ misc/    материалы
```

## Два вида материалов

**Тест** — стиль Macmillan photocopiable, подсчёт баллов, отправка результата учителю
через Formspree. Палитра своя у каждого юнита: `test.css` держит только структуру,
цвета материал задаёт у себя в `:root`.

**Воркшит** — фирменный стиль ANGLE: Apercu Pro, `#5E4877` / `#FED500`, логотип,
прямые углы. Самопроверка, оценка учителю не уходит.

Отправка не привязана к виду — блок можно добавить в любой материал.

## Шрифт

Apercu Pro (Colophon Foundry) — коммерческий. В репозитории только сжатые `woff2`
по 37 КБ; исходные `.otf` в git не попадают, они в `.gitignore`.
Из шрифта выброшена мёртвая таблица `kern` (65 КБ, браузеры её не используют для
OpenType — кернинг берётся из `GPOS`), после чего 160 КБ превратились в 37 КБ
без потери единого глифа.

## Откуда всё взялось

Раньше каждое задание было отдельным сайтом на Netlify, а шрифты и картинки лежали
внутри HTML в base64 — файлы весили до 800 КБ при 30 КБ содержимого.
Подробности решения — в [docs/plan.md](docs/plan.md).

Старые сайты на Netlify не тронуты и продолжают работать; у перенесённых материалов
прежний адрес показан в панели преподавателя.
