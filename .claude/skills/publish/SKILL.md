# Публикация

## 1. Собрать и проверить

```bash
node build.mjs
```

Если упало — прочитать сообщение, оно называет файл и поле. Не публиковать до исправления.

## 2. Показать, что изменится

Перечислить:

- какие материалы добавились или изменились;
- их будущие адреса;
- у каких `status: draft` — они **не появятся** на странице курса, только в панели
  преподавателя. Если материал готов, спросить, переключить ли на `published`.

## 3. Порядок публикации

Проверить, настроен ли `gh`:

```bash
gh auth status
```

**Если настроен** — сделать самому:

```bash
git add -A
git commit -m "Добавлен <название материала>"
git push
```

Затем дать ссылку на вкладку Actions и сказать, что через минуту страница обновится.

**Если не настроен** (обычный случай у Виктории) — не пытаться настраивать,
а сказать словами, что нажать:

> Откройте GitHub Desktop. Слева будет список изменённых файлов.
> Внизу впишите короткое описание, например «Тест по Unit 10».
> Нажмите **Commit to main**, потом синюю кнопку **Push origin** справа вверху.
> Через минуту страница обновится.

## 4. Если изменений не видно

По порядку:

1. Прошла ли минута. Сборка не мгновенная.
2. Нажата ли **Push origin**, а не только **Commit**. Коммит без пуша остаётся на её
   компьютере — это самая частая причина.
3. Вкладка **Actions** на github.com: зелёная галочка — опубликовано, красный крестик —
   сборка упала, открыть лог и прочитать последние строки. Обычно там сообщение
   от `build.mjs` про незаполненные метаданные.
4. Материал в `draft` — тогда он и не должен быть на странице курса.
5. Браузер закешировал страницу — обновить с Ctrl+F5 (Cmd+Shift+R на Mac).
