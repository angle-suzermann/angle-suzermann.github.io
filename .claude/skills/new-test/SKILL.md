# Новый тест

## 1. Собрать вводные

Спросить одним сообщением всё, чего не хватает, — не по одному вопросу:

- курс и номер юнита;
- темы (грамматика и лексика), которые проверяем;
- сколько заданий и примерно сколько вопросов;
- есть ли материалы учебника, на которые опираемся (текст, аудирование, страница).

Если Виктория прислала скан или список слов — этого достаточно, лишнего не спрашивать.

## 2. Определить место

- `course-id` взять из `site.config.json`. Если курса там нет — спросить, добавлять ли новый.
- Путь: `<course-id>/unit<N>-test/index.html`. Если такая папка есть — спросить,
  дополняем существующий тест или делаем второй (`unit<N>-test-2`).

## 3. Создать файл

Скопировать `_templates/test.html` и заполнить.

**Метаданные** — все поля. `ws:status` всегда `draft`: Виктория сама переключит на
`published`, когда проверит. `ws:formspree` — ярлык курса из `site.config.json`.

**Палитра.** У каждого юнита свой цвет — это её приём, не унифицировать.
Подобрать спокойную пару под тему юнита и задать в `:root` материала.
Уже занятые: AS4 Unit 8 зелёная (`--moss:#35664F`), AS5 Unit 9 фиолетовая (`--moss:#7B3FB5`).
Правила: `--moss` — насыщенный, `--moss-dark` — темнее его, `--bg` — очень светлый той же
гаммы, `--paper` почти белый, текст `--ink` тёмный. Контраст текста к фону не ниже 4.5:1.

**Задания.** Размечать по конвенциям из `CLAUDE.md`:
`data-q` + `data-ans` (или `data-ans-list` через `|`), `data-group` + `data-ans` для кнопок.
На каждой `section.card` — уникальный `id` и `data-name` (эта подпись уходит в письмо учителю).

Что важно для учеников:
- задания идут от простого к сложному;
- формулировки на английском, короткие, в повелительном наклонении;
- в `data-ans-list` перечислить все разумные варианты, включая британский и американский
  (`lorry|truck`), иначе верный ответ засчитается как ошибка;
- ученики отвечают с телефона — не делать таблиц шире экрана и полей уже 44px по высоте.

## 4. Проверить

```bash
node build.mjs
```

Дальше сверить самому:

- число вопросов в `progress-label` совпадает с фактическим;
- у каждого `data-q` есть `data-ans` или `data-ans-list`;
- нет повторяющихся `data-q` и `data-group`;
- ответы в `data-ans` действительно верные — перечитать задания глазами;
- ни одного `src="data:..."`.

Затем прогнать `check-material`.

## 5. Сказать, что делать дальше

Сообщить путь, адрес будущей страницы и напомнить: **GitHub Desktop → Commit to main →
Push origin**, через минуту ссылка живая. И что материал пока `draft` — на странице курса
он появится после переключения на `published`.
