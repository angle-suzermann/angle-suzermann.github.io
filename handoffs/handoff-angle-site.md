## Что это за проект

Сайт с интерактивными учебными материалами (тесты и воркшиты по английскому)
для учеников студии Виктории Сюзёвой (ANGLE, «студия системного английского»,
CELT-квалификация, ~16 лет опыта, IELTS/CAE/CPE/ЕГЭ). Каждый материал —
самостоятельная HTML-страница: ученик открывает ссылку (обычно из Telegram),
выполняет задания, страница сама проверяет ответы и присылает результат
учителю на почту. Материалы организованы по курсам/учебникам (Academy Stars,
Empower B1+, Expert Advanced, Gateway, ЕГЭ 2027, Oxford Phonics World,
placement tests и т.д.) — на сентябрь 2026 это **135 материалов** в 11 курсах
(разбивка по курсам — в таблице ниже).

Стек — статический сайт без бэкенда: чистый HTML/CSS/vanilla JS на каждой
странице, `build.mjs` (Node) собирает каталоги курсов и панель преподавателя
из метаданных материалов, GitHub Actions пересобирает и публикует сайт на
каждый push в `main`. Результаты тестов уходят на почту Виктории через
Web3Forms (бесплатный сервис форм — POST из браузера ученика, без своего
сервера).

## Архитектура репозитория

```
site.config.json      список курсов, адрес панели преподавателя — единственный файл,
                       который правят руками при добавлении курса
build.mjs              сборка: валидирует материалы, генерирует catalog.json,
                        страницы курсов и панель преподавателя (/staff-7fk2q9/) в _site/
assets/                 общее для всех материалов, грузится через абсолютные пути /assets/...
  angle.css             бренд ANGLE: шрифт Apercu Pro (только woff2!), палитра, шапка
  test.css               структура/раскладка тестового шаблона (без цветов)
  test-engine.js          подсчёт баллов, разбор ошибок по вопросам, отправка Web3Forms
  sticker-data.js         НОВОЕ (23 сент) — база64-пул из 23 картинок-стикеров
  sticker-logic.js        НОВОЕ (23 сент) — общая логика тиров результата (см. ниже)
  catalog.css             оформление каталогов курсов
  fonts/                  Apercu Pro, только .woff2
  brand/angle-logo.png
_templates/              заготовки test.html / worksheet.html для новых материалов
<course-id>/<slug>/index.html   сами материалы, произвольная вложенность
                                 (unit N / module N / кастомные группы — build.mjs
                                 сам находит на любой глубине)
handoffs/                этот файл + предыдущие планы/хэндоффы
_site/                  СГЕНЕРИРОВАНО, в git не попадает (.gitignore) — не редактировать
```

**Деплой:** Виктория коммитит в GitHub Desktop (`Commit to main` → `Push origin`).
GitHub Actions (`.github/workflows/pages.yml`) на каждый push запускает
`node build.mjs`, публикует `_site/` на GitHub Pages — примерно за минуту.
Правки прямо на github.com тоже работают, сборка запустится и там.

**Важно для сессий на удалённой машине Виктории:** `git push` из
`device_bash` не работает (`fatal: could not read Username for
'https://github.com'` — нет сохранённых кредов в этом шелле). Все коммиты,
сделанные ИИ-сессией, остаются локальными и ждут, пока Виктория запушит их
сама через GitHub Desktop тем же способом, что обычно. Проверка синхронизации:
`git fetch origin main && git merge-base --is-ancestor origin/main HEAD`.

## Правила работы — коротко (полностью см. CLAUDE.md)

Это не пересказ всего `CLAUDE.md` (17 КБ, читайте целиком перед правками —
там разметка тестовых заданий, метаданные `ws:*`, таблица меток курсов для
писем и процедура импорта готовых материалов с диска). Самое важное, что
легко сломать по незнанию:

- **Никогда не встраивать base64** — ни шрифты, ни картинки. Apercu Pro уже
  подключён из `/assets/fonts/*.woff2`; картинки заданий — в `img/` рядом
  с материалом, ссылка `img/имя.png`. Сборка падает, если найдёт
  `src="data:..."`.
- **Не коммитить `.otf`/`.ttf`** — Apercu Pro коммерческий, репозиторий
  публичный. Только `.woff2`.
- **Пути только абсолютные** (`/assets/...`), не относительные — ломаются
  при переносе материала между курсами.
- **Не редактировать `_site/`, `catalog.json`, `<курс>/index.html`** —
  перезаписываются `build.mjs` при каждой сборке.
- **Новый материал начинают со `status: draft`** в `ws:status` — виден в
  панели преподавателя, но не на странице курса, пока Виктория не проверит.
- **Subject-строка писем ученику/учителю всегда включает имя ученика** —
  формат `курс — тема — имя ученика`. Это правило добавилось после аудита
  23 сентября (см. ниже); на сентябрь 2026 весь сайт ему соответствует.
- **Web3Forms — единый бэкенд отправки** (`access_key` зашит в
  `test-engine.js`, endpoint `https://api.web3forms.com/submit`).
  Исключение — страницы с загрузкой файла (запись голоса): те идут через
  Basin. Подробности и таблица меток курсов (`ws:formspree`) — в `CLAUDE.md`.

Обе системы существовали россыпью по десяткам файлов и были в этот день
консолидированы в общие ассеты. **Следующему, кто правит `CLAUDE.md`, стоит

### 1. Система стикеров-наклеек по результату (assets/sticker-logic.js)

На каждой странице теста/воркшита с результатом показывается стикер
(«eggdog»-маскот) в зависимости от процента: `RESULT_TIERS` — таблица
порогов (100/90/75/60/40/0%), у каждого порога свой пул из нескольких
стикеров (выбирается случайно через `pickRandom`), у порогов 40% и 0% есть
текстовая подпись-утешение на случай «молчаливых» стикеров без надписи
(`SILENT_STICKERS`).

**До 23 сентября** эта логика (таблица + 3 функции + рендер) была
продублирована почти дословно в 51 файле, причём тремя разными способами
подключения картинок:
- часть файлов грузила общий `assets/sticker-data.js` (base64-пул) и сама
  подставляла `img.src` в рантайме — правильный паттерн, но с
  продублированным JS;
- часть держала у каждого материала свою копию всех 23 PNG в своей `img/`
  (реальный дубль ≈24 МБ на весь сайт);
- один файл (`opinion-essay-2`, два таба classwork/homework) генерировал
  `<img>` в рантайме через `innerHTML` из своего объекта с локальными путями.

**Что сделано:** создан единственный `assets/sticker-logic.js`
(`RESULT_TIERS`/`SILENT_STICKERS`/`pickRandom`/`getResultTier`/
`renderResultSticker`, обычные globals, без IIFE — специально, чтобы и
`test-engine.js`, и легаси-файлы со своим встроенным скриптом могли звать
эти функции напрямую). 50 файлов переведены на связку
`<script src="/assets/sticker-data.js">` + `<script src="/assets/sticker-logic.js">`,
529 локальных PNG-дублей (24 МБ) удалены. У `opinion-essay-2` (два таба)
сохранена его собственная функция-обёртка `renderResultSticker(tab, pct)` —
там пришлось оставить файл-специфичную часть, но она теперь тоже берёт
картинки из общего `STICKER_DATA`, а не из своих PNG.

**Один файл сознательно НЕ трогали:**
`a2-key-for-schools/Test 6/mock-test-6/index.html` — в его собственном коде
прямым текстом написан комментарий, что это намеренно автономный
однофайловый офлайн-хендаут без обращения к `/assets/` (см. also
`angle-worksheet-template`-скилл, который заранее предупреждал про такой
случай). Если понадобится снова трогать стикеры — этот файл пропускать.

Коммиты: `ac1fb71` (фикс бага — 29 файлов не имели стикера `vzhukh` в пуле
90–100%, т.к. он был добавлен в `sticker-data.js`, но не везде в разметку) →
`ac92682` (сама консолидация, 50 файлов + удаление PNG).

### 2. `.app-shell`/`.scroll-area` вместо sticky/fixed-шапки (Telegram-баг)

12 сентября 2026 живьём в Telegram-браузере был подтверждён и починён баг:
`position:sticky`/`fixed` элементы (топбар, фоновые слои) на секунду
съезжают поверх уже проскроленного контента во время анимации
показа/скрытия нижней панели инструментов Telegram in-app browser —
известный баг WebKit/WKWebView (layout viewport и visual viewport временно
расходятся). Пять попыток компенсации (GPU-хинты, JS-коррекция по
`visualViewport`, `top:-1px` пересчёт) не помогли до конца — сработало
только убрать саму причину:

```css
html,body{ margin:0; padding:0; height:100%; overflow:hidden; } /* документ сам не скроллится */
.app-shell{ position:fixed; inset:0; display:flex; flex-direction:column; overflow:hidden; }
.bg-photo, .bg-wash{ position:absolute; inset:0; /* было position:fixed */ }
.scroll-area{ flex:1 1 auto; overflow-y:auto; -webkit-overflow-scrolling:touch; position:relative; }
/* .topbar — обычный flex-child внутри .app-shell, НЕ sticky и НЕ fixed */
```

Вся страница оборачивается в `.app-shell` (никогда не ресайзится, т.к.
`position:fixed;inset:0`), весь реальный скролл уходит в `.scroll-area`
внутри него. Подтверждённый образец — `empower-b1/Polina/driving-test-classwork`.

К 23 сентября этот паттерн остался не применён в 18 файлах. Разбор кода
(не по названию, а по факту) показал: 16 из них — тот же баг, тот же
механизм, просто на старом паттерне (10 тестов Expert Advanced + 4 файла
empower-b1/unit 4 + `opinion-essay-2` + `placement-tests/academy-stars`,
у последнего своя мелкая специфика: обёртка называется `.wrap`, а не
`.page-wrap`, ANGLE-бейдж расположен в начале body, а не в конце — но это
безопасно, `position:fixed`-элементы не зависят от места в DOM, если
родитель не создаёт новый containing block через `transform`/`filter`).

**2 файла сознательно НЕ мигрированы:**
`expert-advanced/module 3/modals-case-file` и `.../modals-homework` — это
другой, более старый шаблон вообще без `.bg-photo`/`.bg-wash`/`.app-shell`;
`.topbar` там уже `position:relative` (обычный блок в потоке, страница
скроллится нативно браузером). Бага там в принципе нет — переносить в
app-shell не за чем, это меняло бы рабочий шаблон без причины.

Коммит: `57788d4` (16 файлов).

**Визуальная проверка не сделана headless-браузером** (на машине Виктории
нет установленного Chromium, качать не стали) — миграция сделана по
буквально тому же CSS-механизму, что уже подтверждён живьём в Telegram,
но стоит открыть один из тестов Expert Advanced на телефоне в Telegram и
прокрутить, чтобы увидеть тот же результат воочию.

## Особенности рабочего процесса Cowork-сессий на этом проекте

Для следующей сессии, которая продолжит работу через `device_bash`
(удалённая машина Виктории, Windows, изолированная Linux VM):

- Разрешение на удаление файлов (`device_request_delete_permission`) нужно
  запрашивать заново после каждого сброса/переподключения сессии — не
  сохраняется между реконнектами.
- `git push` из `device_bash` не работает в принципе (см. выше) — коммитить
  можно и нужно, пуш — за Викторией.
- Для путей с пробелами/кириллицей — `git -c core.quotepath=false status`,
  `git add --pathspec-from-file=<файл>` (пути без ведущего `./`).
- Перед `git`-операциями полезно `rm -f .git/index.lock` — сессии иногда
  обрываются посреди операции и оставляют лок-файл.
- Валидация перед каждым коммитом с массовой правкой файлов: сухой прогон
  скрипта → проверка балансов (`{`/`}`, `<div>`/`</div>`, `<script>`/`</script>`)
  → `node --check` на извлечённых инлайн-скриптах → `node build.mjs` без
  ошибок → `git status` на ожидаемое число изменённых файлов → коммит.
- Коммит-сообщения — подробные, на русском, с объяснением «почему», не
  только «что». Заканчиваются:
  ```
  Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01SBQmhXTgN3ef1LABLFGMxY
  ```
  (ссылка на сессию — своя для каждой новой сессии, не копировать эту).
