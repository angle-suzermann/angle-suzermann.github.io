# Домашние карточки — заявки ученика и подтверждение учителем

10.11.2026. Дополняет заметки карточек групп и `2026-11-10-movers-unit8-test-reminder.md`.

## Новое правило Виктории

После выполнения карточки ученик может отправить заявку. Это предложение выполнения, как suggested в индивидуальных планах: оно не ставит зелёную галочку и не начисляет баллы. Учитель проверяет и подтверждает существующие пункты трекера. Не пропускать карточки через автоматический worksheetSubmission_, который имеет другую семантику.

## Реализация

- `assets/homework-submit.js?v=2`, явно подключён в пяти карточках: Starters 13.11, Movers 10/12.11, Flyers 10/12.11. Новые карточки должны подключать его один раз.
- Имя, необязательный комментарий/ссылка на фото; отправка после всех локальных галочек. Payload содержит список пунктов, без оценок и учительского токена. Повторная отправка с тем же ID идемпотентна; повтор с новым ID для уже ожидающей/подтверждённой карточки получает прежний receipt.
- Ученик видит pending/confirmed/returned и комментарий. Ошибка сети явно показана, поля и галочки остаются; можно повторить. Обновление статуса каждые30с и кнопкой.
- В `assets/tracker/tracker.js` у учителя сверху список «На проверку». Выбирает один/несколько существующих пунктов Unit/Phonics/Extras; при единственном Extra с таким URL он предвыбран. Затем «Подтвердить выбранное» или «Вернуть на доработку».
- Автоматических новых заданий/баллов нет: иначе карточка могла бы повторно посчитать уже существующие Workbook/Phonics/тест. N/A не выбираются и сервером не заменяются; уже ✓ сохраняются. Проверка всех целей до первой записи, только в том же курсе/ученике. Открытая форма учителя защищена от фонового refresh.
- Родительский read-only вид показывает только заявки своего ребёнка. Изменения индивидуальных планов и обычных автосдач не вносились.

## Сервер

Действующий Apps Script обновлён с v25 до v26 **10.11.2026,14:08 МСК**, прежний ID/URL/доступ сохранены. Сопровождаемый исходник: `Course checklists/Web tracker/Code.gs`; backup/candidate/tests/screenshot: `homework-review-2026-11-10/` рядом. Живой редактор сверялся до правки и после сохранения.

Методы `homeworkSuggestion` и `homeworkStatus` публичные: создают лишь непроверенное заявление, статус выдаётся по случайному ID. `reviewHomework` требует прежний учительский token. Новая вкладка `Homework_Submissions` создаётся лениво при первой реальной заявке. Имя сопоставляется только по единственному активному ученику своего курса с точным нормализованным именем/явным mee alias. Неизвестное/неоднозначное имя отклоняется с видимым сообщением. Произвольные URL, чужие курсы/цели, неполные/повторные пункты отклоняются. Пользовательские значения защищены от формул Sheets.

## Проверки

- Backend VM: только pending при сдаче; изоляция ученика/курса; идемпотентность/дубли; незнакомое имя/неполная сдача; teacher auth; все цели до записи; N/A; существующие ✓; return/resubmit; экранирование формул.
- Edge с полностью перехваченным API: 5 форм на390/1100, нет overflow/pageerror, поля16px; нельзя отправить неполную домашку; pending после reload без зачёта; учитель подтверждает выбранный Extra; ученик видит confirmed. Фиктивные данные, ни одной реальной отметки/письма/заявки.
- Общие submission-hook, submission-transports и tracker-submission-refresh тесты прошли.
- На действующем v26 вызван только homeworkStatus для заведомо несуществующего QA ID: `ok:false, reason:not_found`. Никаких ученических записей.

Локальные комплекты карточек синхронизированы, прежние HTML архивированы вне репозитория. Фото по-прежнему можно присылать Виктории привычным каналом; встроенной загрузки файлов нет, есть поле для ссылки. Не заявлять, что реальная сдача уже была проверена.

Чистая полная сборка прошла (328 материалов). В итоговых пяти карточках скрипт отправки найден ровно по одному разу, teacher review код включён. Изолированный output: homework-review-build. Номер версии скриптов трекера в build вычисляется по хешу содержимого — кэш автоматически обновится.


Отправка блокирует редактирование имени до ответа, а ответ фоновой проверки статуса применяется только к прежнему receipt и тому же имени. Это исключает показ старого подтверждения после смены имени в одном браузере.
