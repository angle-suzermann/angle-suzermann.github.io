# Каталог учебных материалов ANGLE: один репозиторий + GitHub Pages

## Context

Виктория делает интерактивные HTML-материалы (тесты и воркшиты) для учеников с помощью Claude
и выкладывает **каждый файл отдельным сайтом на Netlify**. Из-за этого:

- нет единого места, где видно, какая ссылка какому заданию соответствует;
- список ссылок приходится держать где-то отдельно и вручную;
- каждый новый материал = создание нового сайта.

Вторая, менее очевидная, но более острая проблема — **файлы не пригодны для работы ИИ-агентов**.
Шрифты Apercu Pro и логотип ANGLE вшиты в каждый файл как base64:

| файл | размер | из них реального контента |
|---|---|---|
| `debate_phrases_warmup_HIGHER logo.html` | 668 КБ | 15 КБ |
| `as4_unit8_test (1).html` | 797 КБ | 36 КБ |
| `as5_unit9_test.html` | 37 КБ | 37 КБ |
| `4A_ability_vocabulary_worksheet (1).html` | 35 КБ | 24 КБ |

Claude физически не может нормально читать и редактировать файл на 800 КБ — контекст кончится
раньше. Пока это не исправлено, требование «над папкой работают в первую очередь ИИ-агенты»
не выполняется, каким бы ни был каталог.

**Результат:** один публичный репозиторий на GitHub → один сайт на GitHub Pages, где материалы
лежат по осмысленным путям, индексы генерируются автоматически из самих файлов, а общие ассеты
вынесены наружу.

### Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Хостинг | **GitHub Pages**, публичный репозиторий | см. ниже |
| Домен | пока `<username>.github.io`, свой домен позже | пути внутри сайта не изменятся |
| Индексы | публичная страница на курс + скрытый учительский индекс | внутренний ресурс школы |
| Индексация поисковиками | закрыта (`robots.txt` + `noindex` на каждой странице) | |
| Сборка | `build.mjs` на Node без зависимостей, **не Vite и не SSG** | см. раздел ниже |
| Шрифты | Apercu Pro остаётся, но сабсет + woff2, исходный OTF в git не попадает | |
| Старые сайты Netlify | не трогаем, пусть висят | |
| Объём первого шага | каталог + вынос ассетов | |

**Почему не Netlify.** Связывающее ограничение нового бесплатного тарифа — не трафик, а деплои:
300 кредитов ÷ 15 за продакшн-деплой = 20 деплоев в месяц на всю команду. Реальный цикл
(выложила → опечатка → правка → переформулировка) даёт 3–4 деплоя на материал, то есть
6–8 материалов в месяц пробивают лимит. Трафик при этом ничтожен: страница ≈ 30 КБ после выноса
ассетов, шрифт кешируется один раз на все материалы — 1000 визитов ≈ 20 кредитов. Решающий довод —
режим отказа: при исчерпании кредитов **все** сайты команды гаснут с «Site not available» без
возможности докупить, то есть ссылка на тест умирает посреди учебной недели. Лимиты GitHub Pages
(1 ГБ сайт, ~100 ГБ трафика/мес, 10 сборок в час) мягкие и для этого проекта недостижимы.

**Почему репозиторий называется `<username>.github.io`.** Тогда сайт живёт в корне домена, а не
в подпапке — и `robots.txt` начинает работать (в проектном репозитории он игнорируется, так как
поисковики читают его только из корня домена). Плюс короче ссылки. Цена: расходуется единственный
слот «user site» у аккаунта.

Рядом появляется подпапка `angle-site/` — **готовый репозиторий целиком**, который упаковывается

```

└── angle-site/                    ← ЭТО в zip
    ├── START-HERE.md              ← пошаговая инструкция для неё, по-русски

```

Смысл в том, чтобы Виктория распаковала архив и получила рабочий проект, где уже всё лежит

⚠️ В архиве есть скрытые папки `.github`, `.claude`, `.gitignore`. Они нужны обязательно —

решить, что архив распаковался не полностью.

## Структура репозитория

То, что редактирует агент, лежит ровно там же, где отдаётся браузеру — никакого `src/` → `dist/`.
Сборка только дописывает индексы.

```
<username>.github.io/
├── CLAUDE.md                  # правила для ИИ-агентов — главный файл
├── README.md                  # то же для людей (коллеги)
├── site.config.json           # курсы, Formspree-эндпоинты, путь учительского индекса
├── build.mjs                  # ~150 строк, Node без зависимостей
├── .github/workflows/pages.yml
├── robots.txt                 # Disallow: /
├── assets/
│   ├── fonts/apercu-pro-400.otf      # 164 КБ, был в base64
│   ├── fonts/apercu-pro-700.otf      # 165 КБ, был в base64
│   ├── brand/angle-logo.png          # 9 КБ, был продублирован в 2 файлах
│   ├── angle.css                     # бренд ANGLE: палитра, header, чипы, кнопки
│   ├── test.css                      # структура тестов: hero, card, progress, results
│   └── test-engine.js                # общий скоринг + отправка в Formspree
├── _templates/                # НЕ публикуется (build.mjs не копирует)
│   ├── test.html
│   └── worksheet.html
├── as4/unit8-test/{index.html, img/*.png}
├── as5/unit9-test/index.html
├── as5/unit9-debate-warmup/{index.html, img/cover.png}
└── <course>/4a-ability-vocabulary/index.html
```

Правило путей: материал — всегда `<course-id>/<slug>/index.html` (глубина 2).
`<course-id>/index.html` (глубина 1) — генерируемая страница курса, руками не трогается.

## Метаданные: источник правды — сами файлы

Никакого отдельного `catalog.json`, который надо руками синхронизировать. Каждый материал
несёт метаданные в `<head>`, а `build.mjs` их вычитывает:

```html
<meta name="ws:type"      content="test">          <!-- test | worksheet | warmup -->
<meta name="ws:course"    content="Academy Stars 5">
<meta name="ws:course-id" content="as5">
<meta name="ws:unit"      content="9">
<meta name="ws:title"     content="Unit 9 — What's your opinion? (reported speech)">
<meta name="ws:emoji"     content="📖">
<meta name="ws:date"      content="2026-05-14">
<meta name="ws:status"    content="published">     <!-- draft | published -->
<meta name="ws:formspree" content="mjgnbjkk">      <!-- пусто = без отправки -->
<meta name="ws:tags"      content="reported speech, food, media">
<meta name="ws:legacy-url" content="https://as5-unit9-test.netlify.app/">  <!-- если есть -->
<meta name="robots"       content="noindex, nofollow">
```

Добавить материал = создать папку и положить туда `index.html` с этим блоком. Каталог обновится сам.

## `build.mjs`, и почему не Vite

Vite — сборщик кода приложения: он идёт по графу импортов от точки входа, бандлит модули,
хеширует имена файлов и минифицирует. Здесь графа нет — есть четыре независимых рукописных HTML
и три общих статических файла. Что конкретно дал бы Vite:

| фича Vite | нужна ли |
|---|---|
| бандлинг модулей | нечего бандлить: `angle.css`, `test.css`, `test-engine.js` |
| минификация | страница 15 КБ, экономия ~4 КБ |
| dev-сервер с HMR | она правит HTML и жмёт reload; модулей и фреймворка нет |
| хеши в именах для сброса кеша | **единственная реальная** — но GitHub Pages отдаёт всё с `Cache-Control: max-age=600`, браузер и так перепроверяет раз в 10 минут |

Против него три довода, и первые два — принципиальные:

1. **Мультистраничному Vite нужен явный список входных файлов** в `build.rollupOptions.input`.
   Добавить материал = отредактировать конфиг сборщика. Это ровно та морока, ради устранения
   которой всё строится («положил папку — появилось в каталоге»).
2. **Vite переписывает пути к ассетам внутри HTML.** Тогда файл, который правит агент, перестаёт
   быть тем, что отдаётся браузеру. Свойство «что редактируешь, то и видишь по тому же пути» —
   основа этой схемы, и оно важнее любой минификации.
3. `node_modules`, лок-файл, мажорные обновления раз в полгода — ещё одна вещь, которая
   ломается у нетехнического владельца репозитория.

Полноценный SSG (Eleventy, Hugo) отпадает по той же причине: он нужен, когда страницы
шаблонизируются из данных, а её материалы штучные — каждый со своей вёрсткой заданий и своей
палитрой. Единственное, что здесь действительно шаблонизируется, — индексы, и это делает `build.mjs`.

Обычный Node, ноль зависимостей, запускается в CI и локально. Что делает:

1. Копирует всё в `_site/`, **кроме** `_templates/`, `.github/`, `build.mjs`, `*.md`, `site.config.json`.
2. Сканирует `<course-id>/*/index.html` — список курсов берётся из `site.config.json`, поэтому
   `assets/`, `_templates/`, `.github/` под сканирование не попадают в принципе. Регуляркой
   достаёт `ws:*` из `<head>`.
3. Валидирует: обязательные поля на месте, `course-id` совпадает с папкой, нет дублей путей,
   `ws:formspree` есть у всего с блоком отправки. **При ошибке — падает**, чтобы кривой материал
   не уехал в прод.
4. Генерирует:
   - `_site/index.html` — минимальный лендинг **без списка материалов** (корень ничего не выдаёт);
   - `_site/<course-id>/index.html` — публичная страница курса, только его материалы со
     `status: published`. Эту ссылку она даёт классу;
   - `_site/<staff-path>/index.html` — учительский индекс: все курсы, включая черновики;
   - `_site/catalog.json` — машиночитаемый каталог для агентов.

Учительский индекс — то, ради чего всё затевалось, поэтому в нём:

- фильтры по курсу / типу / юниту и поиск по названию (клиентский JS, ~40 строк);
- **кнопка «копировать ссылку»** у каждого материала — это её ежедневная операция;
- куда уходят сабмиты (Formspree-эндпоинт) и статус `draft`/`published`;
- ссылка на исходник в GitHub.

Путь учительского индекса берётся из `site.config.json` (например `staff-7fk2q9`), чтобы он
не угадывался. Закладка в браузере + строка в README.

## Вынос ассетов

Проверено по хешам содержимого:

- логотип ANGLE (9328 Б, `sha1 f4a16057`) **побайтово одинаков** в воркшите и в debate-warmup → `assets/brand/`;
- Apercu Pro, два начертания (164 + 165 КБ) — только в debate-warmup → `assets/fonts/`, теперь доступен всем материалам;
- 9 иллюстраций в `as4_unit8_test` (584 КБ) и обложка в debate-warmup (163 КБ) уникальны →
  в `img/` рядом со своим материалом.

### Шрифты: OTF → сабсет → woff2

Разбор таблиц обоих файлов (`sfnt OTTO`, то есть OpenType/CFF):

```
Apercu Pro Regular / Black, Version 4.001, Colophon Foundry
kern=65538 B   CFF=46923 B   GPOS=34166 B   GSUB=8632 B   hmtx=3472 B
636 глифов: latin-basic 95, latin-1 96, latin-ext-A 126, cyrillic 104
```

Два вывода:

1. **`kern` (65 538 Б) — 40% файла и она мёртвая.** Это legacy-таблица кернинга времён TrueType;
   у шрифта есть современный `GPOS`, и браузеры для OpenType используют именно его. 128 КБ
   балласта на два начертания выбрасывается без каких-либо визуальных последствий.
2. **Кириллица в шрифте есть (104 глифа) и нужна** — интерфейс тестов русский («Отправить
   результат учителю», «Сначала нажмите “Проверить ответы”»). Из сабсета её исключать нельзя.

Конвейер (разово, вручную, `pyftsubset` из `fonttools[woff]`):

```
--drop-tables+=kern
--unicodes=U+0020-007E,U+00A0-00FF,U+0100-017F,U+0400-04FF,U+2010-2027,U+20BD
--layout-features='kern,liga,calt'
--flavor=woff2
```

Ожидаю **~20–30 КБ на начертание вместо 164 КБ**: `CFF` при урезании с 636 до ~300 глифов падает
примерно вдвое, `GPOS` — сильнее (пары кернинга для выброшенных глифов уходят), сверху Brotli.
Итог 330 КБ → ~50 КБ на оба начертания. Цифру измерить и записать в `README.md` фактическую.

`font-display: swap` в её `@font-face` уже стоит — сохранить.

**Исходный OTF в git не попадает никогда.** Apercu Pro — коммерческий шрифт Colophon Foundry
(«All rights reserved», плюс маркер `|DCNT` в copyright, похожий на идентификатор экземпляра),
а репозиторий публичный. Конвертация делается вне репозитория, в репозиторий коммитятся только
урезанные woff2. `fonttools` ставится разово в venv/через `uvx` — **зависимостью проекта не
становится**, репозиторий остаётся без `package.json` и `requirements.txt`.
В `.gitignore` добавить `*.otf`, `*.ttf` как страховку от случайного коммита.

Отдельно стоит проверить её лицензию у Colophon: файл десктопный (OTF), а веб-встраивание
обычно продаётся отдельной webfont-лицензией. Это не блокирует работу — шрифт и так публично
раздаётся с Netlify сегодня, — но знать об этом ей полезно.

CSS делится на два общих файла — они соответствуют двум реально существующим дизайн-системам:

- **`angle.css`** — бренд ANGLE (`--purple:#5E4877`, `--yellow:#FED500`, `--black:#2D2926`,
  Apercu Pro, логотип, подпись «by Viktoria Syuzyova»). Используют воркшит 4A и debate-warmup.
- **`test.css`** — «Macmillan photocopiable test» (Space Grotesk / Inter / JetBrains Mono,
  `.info-box`, `header.hero`, `.progress-shell`, `section.card`, `.check-bar`, `.results-panel`).
  Используют оба теста.

**Палитра остаётся за материалом.** У AS4 зелёная (`--moss:#35664F`), у AS5 фиолетовая
(`--moss:#7B3FB5`) — это её приём варьировать цвет от юнита к юниту, и его надо сохранить.
Поэтому `test.css` держит только структуру, а материал переопределяет переменные в своём
маленьком `<style>` в `<head>`.

### Общий `test-engine.js`

Скоринговый JS двух тестов совпадает на ~95% (244 и 243 строки, различий по существу — пять мест).
Извлечение почти механическое:

| было | станет |
|---|---|
| `.item[data-group]` (AS4) / `.dialog-line[data-group]` (AS5) | единый селектор `[data-group]` |
| `const answerKey = {...}` в скрипте | `data-ans` прямо на элементе группы |
| `const sectionNames = {...}` в скрипте | `data-name` на `section.card` |
| `test: 'AS4 Unit 8'` в payload | из `<meta name="ws:title">` |
| `fetch('https://formspree.io/f/mjgnbjkk')` | из `<meta name="ws:formspree">` |

Поддержка `data-ans-list` (несколько верных вариантов через `|`) есть только в AS5 — берём её
в общий движок как надмножество. Заодно убирается мёртвый код в AS4 (вычисляемая и никем
не используемая `correctVal`).

**Debate-warmup оставляем с его собственным JS.** У него другая разметка ответов
(`<form>` + radio + `data-answer`/`data-type` на `.item`), подведение под общий движок потребует
переписать разметку заданий — это уже не вынос ассетов, а рефакторинг контента. Помечаем как
следующий шаг; на размер файла это почти не влияет, так как весь вес там был в шрифтах.

## `CLAUDE.md` — то, что делает папку пригодной для агентов

Ради этого файла всё и строится. Содержание:

- карта репозитория и правило путей `<course-id>/<slug>/index.html`;
- **как добавить материал**: скопировать шаблон из `_templates/`, заполнить блок `ws:*`, положить
  в папку курса;
- **запреты**: не встраивать шрифты, логотип и картинки в base64 (именно это сломало файлы);
  не редактировать сгенерированные `<course-id>/index.html` и `catalog.json`;
- когда какой шаблон: `test.html` (Macmillan-стиль, со сдачей результата) против
  `worksheet.html` (бренд ANGLE, самопроверка); блок отправки подключается в любой из них;
- таблица «курс → Formspree-эндпоинт» — сейчас `mjgnbjkk` для тестов Academy Stars,
  `mlgqeayn` для debate-warmup;
- конвенции разметки заданий: `data-q`, `data-ans`, `data-ans-list`, `data-group`, `data-name`;
- как проверить локально: `node build.mjs && python3 -m http.server 8080 -d _site`.

Отдельно: её существующий скилл Claude для воркшитов надо переписать так, чтобы он брал шаблон
из `_templates/` и подключал `assets/`, а не генерировал самодостаточный файл с base64 внутри.
Иначе проблема вернётся с первым же новым материалом.

## Деплой

`.github/workflows/pages.yml` — стандартный Pages-через-Actions: `checkout` → `setup-node` →
`node build.mjs` → `upload-pages-artifact` (path: `_site`) → `deploy-pages`. Ветки `gh-pages` нет.
В настройках репозитория Pages source = **GitHub Actions**.

Сборка в CI (а не закоммиченные индексы) убирает риск устаревшего каталога, если материал добавят
через веб-интерфейс GitHub, минуя локальный запуск скрипта.

## `START-HERE.md` — инструкция для Виктории

Пишется по-русски, для человека без терминала. Ключевое решение, на котором держится вся
инструкция: **git-операции делает GitHub Desktop (кнопками), а не командная строка.**

Почему именно так — проверено по документации, а не предположено: GitHub-интеграция Claude
в Chat и Projects **работает только на чтение** («Only files (names and contents) in a repo on
a specific branch are synced. We do not retrieve commit history, PRs, or other metadata»),
коммиты, ветки и PR через неё создавать нельзя. Значит связка такая:

- **Cowork** — даёт Claude локальную папку, он в ней читает `CLAUDE.md`, берёт шаблоны и
  сохраняет готовый материал обратно в ту же папку;
- **GitHub Desktop** — превращает изменения в папке в коммит и push двумя кнопками;
- **GitHub Actions** — увидев push, сам собирает и публикует сайт.

### Содержание инструкции

**Часть 1. Разовая настройка (~20 минут, делается один раз)**

1. Аккаунт на GitHub.
2. Распаковать архив в постоянное место (`Документы/angle-site`), не в «Загрузки».
   Блок про скрытые папки.
3. Установить GitHub Desktop, войти в аккаунт.
4. GitHub Desktop → **File → Add local repository** → выбрать папку → «create a repository here»
   → **Publish repository** → имя строго `<её-логин>.github.io`, галку «Keep this code private»
   **снять** (иначе Pages не заработает на бесплатном тарифе).
   Этот путь короче, чем «создать репозиторий на сайте, потом склонировать, потом скопировать
   файлы» — одна операция вместо трёх.
5. На github.com → репозиторий → **Settings → Pages → Source: GitHub Actions**.
6. Вкладка **Actions**: дождаться зелёной галочки (первая сборка ~1 минута).
7. Открыть `https://<логин>.github.io/` — сайт живой. Открыть учительский индекс по адресу
   из `site.config.json` и **положить его в закладки** — это её главная страница.
8. Установить приложение Claude, в Cowork выдать доступ к папке `angle-site`.

**Часть 2. Ежедневный цикл (то, ради чего всё)**

> «Сделай тест по Unit 10 Academy Stars 5, темы такие-то» → Claude создаёт папку с материалом →
> переключиться в GitHub Desktop → **Commit to main** → **Push origin** → через минуту ссылка
> живая, материал сам появился в каталоге курса и в учительском индексе.

Со скриншотами того, что именно нажимать в GitHub Desktop — это единственное незнакомое окно
во всём процессе.

**Часть 3. Что делать, когда что-то не так**

- сайт не обновился → вкладка Actions, красный крестик = сборка упала, открыть лог;
- частая причина падения — незаполненный блок `ws:*`, `build.mjs` ругается прямо в логе;
- как откатить неудачную правку через History в GitHub Desktop;
- как позвать коллегу: Settings → Collaborators.

**Часть 4. Что поменялось в её привычках**

- Больше не создавать сайты на Netlify под каждый материал.
- Старые ссылки продолжают работать, их не трогаем.
- Formspree остаётся как был — сабмиты по-прежнему падают на почту по папкам курсов.

## Скиллы в `.claude/skills/`

Кладём в архив готовыми, чтобы проект работал «из коробки». Каждый — папка со `SKILL.md`
(frontmatter `name` + `description`, дальше инструкция). Они кодифицируют то, что сейчас живёт
в её голове и в одном описании процесса.

| скилл | что делает |
|---|---|
| **`new-test`** | Тест в стиле Macmillan. Спрашивает курс, юнит, темы и количество заданий; копирует `_templates/test.html`, заполняет `ws:*`, размечает задания через `data-q` / `data-ans` / `data-ans-list` / `data-group`, подключает `test-engine.js`, подставляет Formspree-эндпоинт курса из `site.config.json`, задаёт палитру юнита. В конце прогоняет `build.mjs`. |
| **`new-worksheet`** | Воркшит в бренде ANGLE: `angle.css`, логотип, подпись «by Viktoria Syuzyova», самопроверка без отправки. Блок отправки подключается по запросу. |
| **`check-material`** | Проверка перед публикацией: все `ws:*` на месте, **нет base64**, у каждого `data-q` есть `data-ans`, счётчик вопросов сходится с заявленным, Formspree указан если есть кнопка отправки, вес файла < 20 КБ. |
| **`import-material`** | Взять старый самодостаточный HTML (её нынешний формат), вынуть base64 в `assets/` и `img/`, подключить общие CSS/JS, проставить метаданные, разложить по папке курса. Нужен, потому что у неё почти наверняка есть материалы помимо этих четырёх. |
| **`publish`** | Собрать, показать что изменится в каталоге, и напомнить последовательность кнопок в GitHub Desktop. Если технический друг настроит `gh auth login` — сам коммитит и пушит. |

Отдельно: её нынешний скилл для воркшитов надо переписать — сейчас он генерирует
самодостаточный файл со вшитым base64, то есть воспроизводит ровно ту проблему, которую мы
чиним. `new-worksheet` его заменяет.

## Порядок работ

Всё делается в `angle-site/`, исходные файлы в `angle/` не трогаются.

1. Создать `angle-site/`, распаковать base64 из четырёх файлов в `assets/` и `img/`
   (скриптом, а не руками).
2. Шрифты: выбросить `kern`, сабсет, woff2 — **вне репозитория**, в проект кладём только результат.
3. Разложить материалы по `<course-id>/<slug>/`, проставить блоки `ws:*`.
4. Вынести `angle.css`, `test.css`, `test-engine.js`; переключить материалы на них.
5. Написать `build.mjs` + шаблоны индексов, прогнать локально.
6. Написать `CLAUDE.md`, `README.md`, `site.config.json`, `robots.txt`, `.gitignore`,
   `_templates/*`, `.github/workflows/pages.yml`.
7. Написать пять скиллов в `.claude/skills/`.
8. Написать `START-HERE.md`, положить план в `docs/plan.md`.
9. **Проверить локально всё целиком** (раздел ниже) — до отправки, потому что чинить по переписке
   будет неудобно.
10. Упаковать `angle-site/` в zip.

Скриншоты GitHub Desktop для `START-HERE.md` придётся сделать вручную — у меня их взять неоткуда.
Либо оставляю в инструкции текстовые метки кнопок и пометку, куда вставить картинки.

## Verification

Локально (`node build.mjs && python3 -m http.server 8080 -d _site`):

Функционально — построчно сверить со старой версией, тесты уже работают и регрессия недопустима:

- **Скоринг.** Пройти `as4/unit8-test` и `as5/unit9-test` целиком, сверить `N / TOTAL` и проценты

  папку Formspree (`mjgnbjkk`), с процентом и разбивкой по секциям. Проверить и debate-warmup
  (`mlgqeayn`) — его JS не менялся, но `<meta>` вокруг него менялось.
- **Валидация формы.** Отправка без имени и до нажатия «Проверить ответы» по-прежнему даёт ошибку.

Внешний вид и вес:

  странице берётся из кеша. Заголовки не должны съезжать на системный шрифт.

- **Вес.** Каждый `index.html` < 20 КБ; оба woff2 суммарно < 60 КБ.

### Прогон всей цепочки на своём аккаунте — до отправки

Инструкцию нельзя отдавать непроверенной: если Виктория споткнётся на шаге 4, отлаживать
придётся по переписке. Поэтому технический друг сначала проходит `START-HERE.md` **сам,
буквально по пунктам**, на своём GitHub-аккаунте:

1. Создать тестовый репозиторий (можно `<его-логин>.github.io`, если слот свободен, иначе
   обычный проектный — тогда проверить, что относительные пути не поехали).
2. Проделать шаги 4–7 инструкции ровно как написано, не додумывая пропущенное.
   Всё, что пришлось додумать, — дырка в инструкции, её закрыть.
3. Дождаться зелёной сборки в Actions, открыть сайт, пройти тест целиком **с телефона**
   и отправить реальный сабмит — письмо должно прийти в Formspree.
4. Проверить, что падение сборки выглядит понятно: временно испортить `ws:*`, запушить,
   убедиться, что в логе Actions видно внятное сообщение от `build.mjs`, а не стектрейс.
5. Репозиторий удалить.
