## Как применять дальше

1. Для новых совместных писем использовать assets/collab.js и _templates/collab-snippet.html. build.mjs сам добавит кнопку в панель.
2. При изменении модуля/подключения совместного письма сохранить автоматическое обнаружение материала и учительскую кнопку в build.mjs.
3. После сборки проверить кнопку в _site/staff-7fk2q9/index.html и ученическую ссылку без teacher в публичном каталоге курса.
4. Не откатывать исправление фокуса. Не считать временную повторную установку focus() решением: активный textarea должен оставаться в DOM без перемещения своего контейнера.

## 28 октября: комментарии учителя к ответам

- В assets/collab.js у каждого ответа/абзаца в учительском режиме есть «Добавить комментарий», затем «Сохранить комментарий», «Изменить комментарий», «Удалить». Ученик видит сохранённое замечание под текстом в реальном времени, без редактора комментария. Работает в blocks и shared.
- Комментарий хранится как feedback:{text,updatedAt} внутри соответствующего blocks/<id> или paras/<id>. Эти пути совместимы с существующими правилами Firebase из шаблона, новых правил/настройки базы не нужно. Не переносить feedback в отдельную ветку rooms/<room>/feedback без обновления правил: такая запись не разрешена текущим шаблоном правил.
- Для ответов queueSend теперь вызывает Firebase update вместо set: патч uid/name/text/ts сохраняет feedback, даже когда ученик пишет одновременно с учителем. Для подставных адаптеров без update есть fallback записи отдельных дочерних полей. Ошибка записи ответа видна в строке состояния.
- DOM редакторов комментария и ответа не пересоздаётся на входящих snapshot. Набор текста/фокус сохраняются. Ошибка сохранения комментария оставляет черновик для повторной попытки. Удаление ответа/комнаты удаляет вложенные комментарии вместе с ним.
- Комментарии выводятся через textContent, HTML в замечании не выполняется. В шаблоне и двух материалах обновлена ссылка collab.js?v=2. Обоим участникам нужно обновить старые открытые вкладки: старый клиент с set целого ответа ещё может затереть новое feedback.
- docs/tests/collab-feedback.cjs: два отдельных browser context с общей mock-базой, оба режима, учитель→ученик live, reload, изменение/удаление, параллельная запись ответа и комментария, фокус/черновики, ошибка записи, HTML, мобильная ширина. collab-delete.cjs также прошёл. Реальную Firebase и настоящие ответы при тестах не меняли.

## 28 октября: пустая страница / падение вкладки на совместном письме

На живом Informal Email выполнена только диагностика чтением в учительском режиме. Комната подключалась, 3 карточки, scrollHeight 13826 CSS px. ws-tools пытался создать ДВА холста по 2560×27652 px при DPR2: около 566 MB только на RGBA-буферы, ещё больше на DPR3. Это объясняет нехватку памяти/падение renderer (в iframe — значок сломанной страницы). Сами ответы и Firebase не изменяли.

assets/ws-tools.js resize теперь ограничивает каждый backing bitmap 4 млн пикселей и размером стороны 8192; CSS-размеры и координаты сохранённых аннотаций прежние. На длинных страницах уменьшается только разрешение рисования. Версия автоматически подключаемого скрипта WT_VERSION=4. Комментарии сохранены.

Регрессия docs/tests/collab-page-memory.cjs открывает ПОЛНЫЙ собранный Informal Email со всеми общими скриптами, 9 длинными ответами и комментариями в mock adapter: phone DPR3 / desktop DPR2, scrollHeight>10000, проверка лимитов буферов, навигации, набора учеником и комментария учителя, отсутствие crash/errors. ws-tools-collapse также проверяет, что рисование/undo/redo/сворачивание продолжают работать. При таком типе изменений не ограничиваться fixture одного collab-компонента: он не включает общий слой рисования.

### Видимость сохранённого комментария и прямые действия
После подтверждения set/remove локальная модель feedback обновляется сразу: текст не исчезает из карточки до прихода очередного snapshot. В режиме просмотра рядом с «Изменить комментарий» добавлена видимая кнопка «Удалить комментарий»; прежнее удаление внутри редактора также доступно. Ссылка collab.js?v=3.

collab-feedback.cjs дополнен сценарием, когда backend уже подтвердил save, но value-snapshot задержан: учитель сразу видит сохранённый текст и обе кнопки. Прямое удаление работает без входа в Edit. Старые открытые ученические вкладки надо обновить — до версии с update они перезаписывают весь answer через set и могут стереть вложенный feedback.
