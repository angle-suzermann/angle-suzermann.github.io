# Начните отсюда

Это готовый сайт со всеми вашими материалами. Внутри уже лежат четыре задания,
которые были на Netlify, — их переносить не нужно.

Что изменится в вашей жизни после настройки:

- **одна страница со списком всех материалов** и кнопкой «копировать ссылку» у каждого;
- новый материал появляется в списке сам, ссылки вручную записывать больше не надо;
- новый сайт на Netlify под каждое задание создавать не нужно;
- страницы стали в 20–50 раз легче и быстро открываются с телефона.

Настройка занимает минут двадцать и делается один раз.

---

> ⚠️ **Сначала — про скрытые папки.**
> В архиве есть три служебные папки, имена которых начинаются с точки:
> `.github`, `.claude`, `.gitignore`. Finder на Mac и Проводник в Windows их **не показывают** —
> вам будет казаться, что архив распаковался не полностью. Это нормально, они на месте.
>
> Без `.github` сайт не будет публиковаться, без `.claude` не будет работать помощь Claude.
> Поэтому распаковывайте архив целиком и **не пересобирайте папку вручную**,
> перетаскивая файлы по одному.

## Часть 1. Настройка — один раз

### Шаг 1. Аккаунт на GitHub

Если его нет — заведите на [github.com](https://github.com). Бесплатного хватит с запасом.

**Запомните свой логин** — он попадёт в адрес сайта. Логин `viktoria` даёт адрес
`viktoria.github.io`. Логин виден всем, кто откроет ссылку, так что выбирайте
такой, который не стыдно показать ученикам и родителям.

### Шаг 2. Распакуйте архив в постоянное место

Не в «Загрузки» — оттуда папки легко удаляются случайно. Хорошее место:
`Документы/angle-site`.

### Шаг 3. Установите GitHub Desktop

Скачать: [desktop.github.com](https://desktop.github.com). Войдите под своим аккаунтом.

Это программа с кнопками, командную строку открывать не придётся. Её работа — забирать
изменения из папки на вашем компьютере и отправлять их в интернет.

### Шаг 4. Опубликуйте папку

В GitHub Desktop:

1. **File → Add local repository**
2. Выберите папку `angle-site`
3. Появится надпись, что это не репозиторий, и ссылка **«create a repository»** — нажмите её
4. В открывшемся окне нажмите **Create repository** (ничего менять не надо)
5. Вверху появится синяя кнопка **Publish repository** — нажмите
6. В окне публикации:
   - **Name** — впишите строго `ВАШ-ЛОГИН.github.io`
     (например, для логина `viktoria` — `viktoria.github.io`, точно так, с точкой)
   - галочку **«Keep this code private» СНИМИТЕ**
   - нажмите **Publish repository**

> Почему репозиторий обязательно открытый: бесплатный GitHub публикует сайты только
> из открытых репозиториев. Ничего лишнего это не раскрывает — ваши задания и так
> открыты по ссылке, а правильные ответы всегда лежали внутри страницы,
> их видно через «Просмотр кода страницы» в браузере.
>
> Почему имя именно такое: репозиторий с именем `логин.github.io` даёт сайт
> в корне адреса — ссылки получаются короткие, и его можно закрыть от поисковиков.

<!-- СКРИНШОТ: окно Publish repository с заполненным Name и снятой галочкой -->

### Шаг 5. Включите публикацию сайта

1. Откройте github.com, зайдите в свой новый репозиторий
2. **Settings** (шестерёнка вверху) → в левом меню **Pages**
3. В разделе **Source** выберите **GitHub Actions**

Больше на этой странице ничего трогать не нужно.

<!-- СКРИНШОТ: Settings → Pages, Source = GitHub Actions -->

### Шаг 6. Дождитесь первой сборки

Вкладка **Actions** вверху репозитория. Там будет строчка «Публикация сайта»
с жёлтым кружком — идёт сборка. Через минуту кружок станет зелёной галочкой.

Если появился красный крестик — загляните в [«Если что-то пошло не так»](#часть-3-если-что-то-пошло-не-так).

### Шаг 7. Проверьте и сохраните закладку

Откройте `https://ВАШ-ЛОГИН.github.io/` — увидите заглавную страницу.

Теперь главное. Откройте:

```
https://ВАШ-ЛОГИН.github.io/staff-7fk2q9/
```

Это **ваша панель** — список всех материалов с поиском, фильтрами и кнопкой
«копировать ссылку». **Положите её в закладки**, вы будете открывать её каждый день.

Адрес нарочно такой странный, чтобы ученик его не угадал. Он записан в файле
`site.config.json`, поле `staffPath` — при желании поменяете.

Страницы для учеников устроены иначе — на каждый курс своя:

- `https://ВАШ-ЛОГИН.github.io/as4/` — Academy Stars 4
- `https://ВАШ-ЛОГИН.github.io/as5/` — Academy Stars 5

Такую ссылку можно дать классу целиком: ученик увидит материалы только своего курса.

### Шаг 8. Подключите Claude к папке

Установите приложение Claude, откройте **Cowork** и дайте ему доступ к папке `angle-site`.

Claude прочитает файл `CLAUDE.md` внутри и сразу поймёт, как у вас всё устроено:
где шаблоны, как оформлять задания, куда складывать новые материалы, куда идут результаты.
Объяснять это заново каждый раз не нужно.

## Часть 2. Как работать дальше

Обычный день выглядит так:

**1. Просите Claude сделать материал.** Прямо словами:

> Сделай тест по Unit 10 Academy Stars 5. Темы: past perfect и путешествия.
> Шесть заданий, примерно 50 вопросов.

Claude сам возьмёт шаблон, оформит в вашем стиле, подставит нужный адрес Formspree
и положит папку куда надо.

**2. Открываете GitHub Desktop.** Слева — список изменённых файлов.
Внизу впишите короткое описание, например «Тест по Unit 10».

**3. Нажимаете `Commit to main`,** потом синюю **`Push origin`** справа вверху.

<!-- СКРИНШОТ: GitHub Desktop с полем описания, кнопкой Commit to main и Push origin -->

**4. Через минуту** ссылка живая, материал сам появился в вашей панели и на странице курса.

**5. Копируете ссылку** кнопкой в панели и отправляете ученикам.

### Черновики

Новые материалы Claude помечает как **черновик**. Черновик виден в вашей панели
(с оранжевой пометкой), но **не попадает** на страницу курса — ученики его не увидят.

Когда проверили и всё нравится, скажите Claude «опубликуй его» — или сами найдите
в файле строчку `<meta name="ws:status" content="draft">` и замените `draft` на `published`.

### Что осталось как было

**Formspree не меняется.** Результаты тестов приходят на почту так же, по папкам курсов.

**Старые ссылки на Netlify работают.** Мы их не трогали — то, что вы уже разослали,
продолжает открываться. Просто новые материалы теперь живут здесь.

## Часть 3. Если что-то пошло не так

### Сайт не обновился

По порядку:

1. **Прошла ли минута?** Сборка не мгновенная.
2. **Нажали ли `Push origin`,** а не только `Commit to main`? Это самая частая причина:
   коммит без пуша остаётся на вашем компьютере.
3. **Вкладка Actions** на github.com. Зелёная галочка — опубликовано.
   Красный крестик — сборка упала, читайте следующий пункт.
4. **Материал в черновиках?** Тогда на странице курса его и не должно быть.
5. **Браузер показывает старое?** Обновите с Cmd+Shift+R (Mac) или Ctrl+F5 (Windows).

### Страница открылась, но выглядит «голой»

Нет цветов, шрифт обычный, логотип не виден, картинки квадратиками — значит
репозиторий назван **не** `ВАШ-ЛОГИН.github.io`, и сайт лежит в подпапке.

Посмотрите на адрес. Если он вида `avdoshenkov.github.io/что-то-ещё/`, откройте
`site.config.json` и впишите имя этой подпапки:

```json
"basePath": "/что-то-ещё",
```

Сохраните, `Commit to main`, `Push origin`. Через минуту всё встанет на место.
Если репозиторий назван правильно, `basePath` должен оставаться пустым: `""`.

### Красный крестик в Actions

Это не поломка сайта — предыдущая версия продолжает работать, просто новая не опубликовалась.

Нажмите на красную строчку, потом на **build** — внизу будет текст ошибки по-русски.
Почти всегда это незаполненные данные о материале, например:

```
as5/unit10-test/index.html
    не заполнены обязательные поля: ws:unit, ws:title
```

Скажите Claude: «сборка падает вот с такой ошибкой» и вставьте текст — он исправит.

### Я что-то испортила и хочу вернуть как было

В GitHub Desktop вкладка **History** — список всех изменений. Найдите нужное,
щёлкните правой кнопкой → **Revert changes in commit**. Потом `Push origin`.

Ничего не теряется безвозвратно: сохраняется каждая версия каждого файла.

### Хочу дать доступ коллеге

На github.com: **Settings → Collaborators → Add people**, ввести её логин на GitHub.
Дальше она делает шаги 3–8, только вместо «Add local repository» выбирает
**Clone repository** и находит ваш в списке.

## Что где лежит

| Файл или папка | Что это |
|---|---|
| `as4/`, `as5/`, `misc/` | материалы по курсам, одна папка = одно задание |

| `CLAUDE.md` | инструкция для Claude — как всё устроено |
| `docs/plan.md` | зачем всё это сделано именно так |
| `.github/` | то, что публикует сайт. Не трогать |
